Context and memory in an agent

From lesson 1. Token counts below are the lesson's invented examples.

Key facts

  • Context window = everything one call sees: system prompt, tool definitions, messages, tool results, output.
  • Nothing persists between steps unless your program re-sends it. Input at step n = all earlier messages + new ones.
  • A tool result is paid for again on every later step. Total input = sum of each step's input.
  • More context is not better: cost grows and recall drops (context rot).

Where information lives

HomeUse for
ContextInstructions, tool descriptions, current question, results still needed
Notes (memory tool, files)Soft per-student context the agent writes; survives sessions
RetrievalLong reference the agent did not write (manuals): chunk, index, return a few chunks
Database behind a toolFacts that must be exact: training status, bookings

Keeping context small, lightest first

  1. Tools return less.
  2. Clear old tool results.
  3. Compact (summarize); save must-keep facts to notes first.

Retrieval checklist

  • Chunks of a few hundred tokens, labelled with machine and section.
  • Embeddings for meaning, BM25 for exact terms such as error codes; combine them.
  • Under about 200,000 tokens, putting everything in the prompt may be simpler.
