Context and memory in an agent

By the end of this lesson you can say what the model sees at each step, what survives between steps and between sessions, and which of three tools (context, notes, retrieval) holds each piece of the makerspace assistant's information.

Your program runs it, not the model. The result goes back to the model as new text and the model is called again. That "called again" is the heart of today: each call starts with only what you send it.

The context window 2.5 min

The big picture: a model remembers nothing by itself. Everything it knows about your conversation is the text you send it on that call. That text is the context: all the tokens the model sees when it generates (Anthropic). The context window is the maximum number of tokens that fit, counting input and output together.

In an agent, the context holds the instructions, the tool descriptions, the conversation so far, and every tool call and result. Each loop step sends all of it again, plus the newest result. So the context grows with every step, and you pay for input tokens on every call.

Size matters beyond the hard limit. As context grows, the model recalls details less accurately, which Anthropic calls "context rot"; it is gradual, not a cliff (Anthropic). So the goal is the smallest set of useful tokens, not the largest window.

A common mix-up

"The model remembers earlier steps." It is tempting because chat feels continuous. In fact your code resends the history each call; if you left it out, the model would not know it had asked for anything.

When a long session nears the limit, a common fix is compaction: summarize the session and continue in a fresh window with that summary. The lightest form is clearing old tool results (Anthropic). Example: after the assistant reads a 3,000-token manual page to find a laser-cutter power setting, it can keep "Laser cutter: max 60% power for acrylic" and drop the page.

Notes as memory 1.5 min

For facts that must outlive the context, the agent writes notes to storage outside the window and loads them later. Anthropic calls this structured note-taking, and examples include a to-do list or a NOTES.md file (Anthropic).

Your case: a student's training status. Store a small record, such as {"student": "s123", "trained": ["laser", "3d-printer"]}. At the start of a session, your code loads that record into context (a few dozen tokens); when training changes, the agent calls a tool that updates it. Notes are small, exact and cheap, because only what you load costs tokens.

Retrieval 1.5 min

Manuals are too long to put in context every time, and most pages are irrelevant to any one question. Retrieval means fetching only the relevant pieces into context when needed. Two timings exist (Anthropic):

  • Up front: your code searches the manuals (often by embeddings, which match meaning, not just words) before the model call and adds the top pages.
  • Just in time: the model gets a search tool and a page list, and fetches pages itself when it decides it needs them. It is more flexible but costs extra loop steps.

Either way, retrieval and notes differ: notes are things the agent wrote down about a person or task; retrieval searches a large body of existing text.

Anthropic suggests mixing both: load a few essentials up front, retrieve the rest on demand.

Worked example and practice 1 min

Worked example

Request: "Am I trained on the laser cutter, and what is its max power for acrylic?" Illustrative token counts: prompt plus tools 2,000; question 50; a manual page 1,500.

  1. Student record is a note: load it (50 tokens) into context.
  2. Max power is in a long manual, so use retrieval: fetch one page (1,500 tokens), not the whole manual.
  3. Call 1 input is 2,100; call 2 resends that plus the page: 3,600. Total input paid is 5,700 tokens.
Your turn

Same setup, but a third call fetches a second 1,500-token page. Step 1 is given: call 3 input is 3,600 + 1,500 = 5,100. What is the total input paid across all three calls, and where would you save tokens?

Show a solution

2,100 + 3,600 + 5,100 = 10,800 tokens. Saving: after reading the first page, keep only the one setting and clear the page (compaction-style), so call 3 would resend far less.

Summary 0.5 min

  • Context is everything sent on a call; it is resent each step and grows.
  • Between sessions, only what your code saves survives.
  • Notes hold small facts about a person or task; retrieval fetches pieces of large text.
